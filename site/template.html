Overview

OntoRAG turns documents into a governed knowledge graph. Two companion specifications describe the result:

Build vocabulary and dataset format (this page)

The outputs and how they were made: the dataset and its manifest, schema cards, the exported ontology, instance graphs, indexes, build runs, baselines, alignment decisions and governance status.

Provenance and citation ontology (orp:)

The evidence: which source, file, page and passage each resource comes from, how to cite it, and how per-source packs compose and scope a dataset.

Both reuse PROV-O, so a build run that orag:consumed an orp:SourceFile and a mention that orp:mentions a resource sit in the same provenance graph. An orag:Dataset is a void:Dataset whose subsets are orp:Packs.

Dataset format 0.1

A published dataset is a directory, usually a git repository ("GitHub as storage"), that a service can read without a database or a clone. manifest.json at its root is the contract. A consumer reads the manifest, loads the graph and entity index, then streams chunks and vectors, joining them by chunk id.

manifest.json                 the contract (manifest.schema.json)
ontology/
  world.ttl                   the knowledge graph, source of truth
  entities.jsonl              flat entity index (entity.schema.json)
  prefixes.json
content/
  sources.json                source documents and their checksums
  books.json                  pack registry: id → {title, path, requires}
  chunks/<pack>.jsonl         retrievable text (chunk.schema.json)
embeddings/
  config.json
  vectors/<pack>.jsonl        one vector per chunk, same id (embedding.schema.json)

Storing chunks and vectors one file per pack makes a pack a literal slice of the dataset: composition and access scoping reduce to selecting files and named graphs.

Validate a dataset with any JSON Schema validator (draft-07), for example check-jsonschema --schemafile https://ontorag.org/vocab/dataset/0.1/manifest.schema.json manifest.json. The sample is taken from the Ars Magica dataset and passes every schema.

Artifacts and build runs

Every output is an orag:Artifact (a prov:Entity): a schema card, the exported ontology, an instance graph (for the whole dataset or one pack), an index or a quality report. Each carries a checksum, a location and a status. Source documents are not artifacts: they are orp:SourceFiles.

Each execution of a pipeline stage is an orag:BuildRun (a prov:Activity) that records its stage, what it consumed and produced, the software version and the language model. Together these give a reproducible lineage from every triple back to the files and model calls that produced it.

Baselines and alignment

OntoRAG aligns to existing ontologies before inventing anything. A dataset declares the baselines it is aligned with and the role each plays: the domain schema (e.g. rpg-schema) or a supporting vocabulary (schema.org, FOAF, Dublin Core). Each class and property of the exported ontology can state its origin and the alignment decision taken for it: reused as is, extended as a sub-class or sub-property, or induced as new.

Governance status

Language models propose; deterministic code merges; people approve. orag:status records where an artifact stands:

Proposed → Approved → Deprecated  ·  any → Revoked

Only approved schema cards should drive instance extraction, and revoked artifacts must not be served. The review itself is an ordinary prov:Activity associated with the person who approved it.

Changes from 0.1.0

Version 0.2.0 moves the namespace from https://www.ontorag.org/vocab# to https://ontorag.org/vocab#, so that it resolves to this page. It also narrows the vocabulary to build metadata and hands evidence and composition to orp:, removing terms that overlapped with it.

Product, requiresProduct, store, productIdRemoved: entitlements belong to the serving application, which maps what a user holds to orp:Packs
ActivationProfile, enablesGraph, disablesGraphPack selection rules in orp: (access scope and composition)

New: Dataset, SchemaCard, OntologyArtifact, BaselineOntology, Stage, alignment terms, buildOf, languageModel, dimensions, similarityMetric

Dataset format 0.1 was revised compatibly on 2026-09-23: embeddings became optional (ontology and keyword retrieval work without vectors) and chunks gained optional page, page_end and page_label for paginated sources. Every manifest and record valid before remains valid.

On 2026-09-25 the manifest gained an optional embeddings.entity_vectors_glob: embeddings of each entity's label, type and description, for retrieval that goes from a described thing to the thing.

The dataset JSON Schemas moved from https://ontorag.dev/schema/, which does not resolve, to https://ontorag.org/vocab/dataset/0.1/.
